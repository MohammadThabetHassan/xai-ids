# Changes in `revision/xai_ids_revised.py`

These are relative to `xai_ids_multidataset.ipynb`, the script that produced the results in the current draft.

| # | Problem in the original | Effect on reported results | Fix |
|---|---|---|---|
| 1 | Early stopping for XGBoost and LightGBM used the **test set** (`eval_set=[(X_te, y_te)]`). The ensemble also inherited `best_iteration` from it. | Test metrics are optimistically biased. | Stratified **train / validation / test** split (64 / 16 / 20). Early stopping uses validation only. |
| 2 | ANOVA + SHAP feature selection was fitted on a sample of the **whole** dataset, before the split. | Feature choice saw test rows. | Feature selection is fitted on the training partition only. |
| 3 | `RobustScaler` was fitted on the whole dataset before the split. The paper says "fitted on training data only". | Minor leakage, and the paper misdescribes the method. | The scaler is fitted on the training partition only. |
| 4 | The paper says the split is 70/30. The code uses 80/20. | The methods section was wrong. | The split is configured explicitly, recorded in `summary.json`, and the paper must quote it. |
| 5 | **CSE-CIC-IDS-2018 loaded as only 2 classes.** One day's CSV (Tue-20-02) has extra ID columns (`Flow ID`, `Src IP`, `Src Port`, `Dst IP`). After concatenation those columns are NaN for every other file, and `dropna()` ran *before* the ID columns were removed. That deleted every row from the other nine days. | The paper blamed the Kaggle source. The source actually has about 15 classes. The 0.999 F1 comes from a trivial binary task. | ID columns are removed per file before concatenation. Files are aligned on their shared columns, and repeated header rows inside CSVs are filtered out. Reproduced and verified on a fixture: the original logic gives `['Benign', 'DDoS attacks-LOIC-HTTP']`, the fixed logic keeps all classes. |
| 6 | `Src Port` and `Dst Port` were **kept** for CIC-2018, because the drop list only had the 2017 spellings (`Source Port`, `Destination Port`). Both appear among the top-5 SHAP features. | Shortcut features (ports) inflate 2018 results and its explanations. | Ports are dropped in every dataset. |
| 7 | **XCS instability** was `np.std(nbr_svs) / mean_abs`. That is the std over the flattened neighbour × feature array, i.e. the spread *across features*, not across perturbations. It hit the 0.5 cap for **every** sample (74/74, 80/80, 86/86). | The term was a constant 0.15 in every Mode A XCS. | Instability is `1 − mean Spearman ρ(|SHAP(x)|, |SHAP(x+ε)|)` over neighbours, in [0, 1]. A CV-style variant is also saved for comparison. |
| 8 | **SHAP–LIME Jaccard** compared SHAP feature names with LIME *condition strings* (e.g. `Fwd IAT Std <= 14.59`), which never match. Jaccard was 0 for **every** sample. | The term was a constant 0. Together with #7, Mode A XCS was exactly `0.4·conf + 0.15`, so the "XCS separates correct from wrong" result is a result about softmax confidence. | LIME features are read by index from `explanation.as_map()`. |
| 9 | XCS was evaluated on 74–86 samples, taken as the *first* n samples of each class. CIC-2018 had 0 errors. | No statistical power, and not a random sample. | XCS uses a natural random sample (1,500 test / 800 val) plus up to 400 extra misclassified samples per split. Flag rates come from the natural sample only. |
| 10 | "Mode B" (`scripts/recompute_xcs.py`) fed `rng.randn` Gaussian noise through the scaler as a "synthetic test set". It has no labels. | None of the Mode B numbers (0.274→0.386, 98/100, 72/100, 5/100, "38 samples") describe network traffic. | Removed from the evaluation. The paper must not use Mode B. |
| 11 | XCS was never compared with the obvious baseline: confidence alone. | The contribution was untested. | AUROC (bootstrap CI) for predicting correctness, for confidence, margin, each component, XCS with the a-priori weights, and XCS with weights learned on validation. Also the paired AUROC difference vs confidence, AURC (risk–coverage), and Cohen's d. |
| 12 | The 0.3 threshold was justified by contradictory arguments ("min is 0.15" / "min is 0.3"). | Not defensible. | Reports the legacy 0.3 and a threshold chosen on validation (Youden J), both evaluated on test: flag rate, error recall, flag precision. |
| 13 | There was **no McNemar code** in the pipeline. The χ² = 892 and p = 0.41 in the paper have no artifact. | Unverifiable. | McNemar for all model pairs (exact binomial if b + c < 25, otherwise χ² with Edwards correction), Holm-adjusted. Saved to `tables/mcnemar.csv`. |
| 14 | No per-class tables were written. The per-class numbers in RESULTS.md and the paper have no source and contradict the saved confusion matrices. | Tables 5 and 6 in the draft are wrong (see the review memo). | Per-class precision, recall, F1, FPR, AP and support are saved for every model. Confusion matrices are saved as CSV plus count and normalised plots. |
| 15 | The beeswarm plotted SHAP for **class index 0** only (Benign / Analysis), but the captions present it as overall importance. | Misleading figures. | The beeswarm uses predicted-class attributions and is labelled as such. Global importance (mean \|SHAP\| over classes) goes to CSV. |
| 16 | The paper reads the "0.216 cross-dataset Jaccard" as cross-dataset feature overlap. It is actually the mean SHAP-vs-LIME agreement over 8 single examples. Cross-dataset name overlap is also confounded by different naming schemes (`Fwd Pkt Len Max` vs `Fwd Packet Length Max`). | A false headline claim. | SHAP–LIME agreement is reported per class over many samples. Cross-dataset comparison uses harmonised names (CIC-2017 vs 2018) and feature-family importance shares. |
| 17 | XGBoost had no class weighting, although the paper says it uses balanced sample weights. | The method was misdescribed. | `compute_sample_weight('balanced')` is used, matching the paper's description. It can be switched off with `XGB_BALANCED_WEIGHTS`. |
| 18 | Latency claims (10 ms / 300 ms) had no measurement. | Unverifiable. | Per-sample time for confidence, SHAP+instability and LIME is saved (median / p95) in `tables/xcs_latency.csv`. |
| 19 | Only weighted F1 was reported. | Hides minority-class failure (CIC-2017 macro F1 is 0.81 against weighted 0.996). | Macro F1, balanced accuracy, bootstrap CIs and ECE are reported. |
| 20 | The final cell force-pushed to GitHub with a token placeholder. | Risky. | Removed. |
